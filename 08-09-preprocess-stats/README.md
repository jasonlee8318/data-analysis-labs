| 회차 | 노트북 | 내용 |
|---|---|---|

| 통계 분석 모듈 개발 | `cafe_stats.ipynb` | 판다스·시본·statsmodels로 상관 히트맵→다중 회귀→결과지 작성 |

## 전처리 회차 상세

카페 매출 예측을 위해 더티 데이터(`cafe_sales.csv`)를 모델 입력이 가능한 상태까지
정제하는 파이프라인을 파이스파크로 작성하는 실습입니다.

탐색 → 결측치 → 이상치(IQR·도메인) → 중복 제거 → 범주형 인코딩 → 피처 벡터 생성

## 사전 준비

1. Docker Desktop 설치·실행
2. 저장소 다운로드 후 `docker compose pull`

## 실습 진행 (두 회차 공통 시작 방법)

```bash
docker compose up -d
```

브라우저에서 http://localhost:8888/?token=spark 접속 → 왼쪽 파일 목록에서
해당 회차의 노트북을 열고 위에서부터 순서대로 실행합니다.

| 회차 | 열 파일 |
|---|---|
| 데이터 전처리 모듈 개발 | `work/cafe_preprocess.ipynb` |
| 통계 분석 모듈 개발 | `work/cafe_stats.ipynb` |

두 회차 모두 같은 환경을 쓰므로, 전처리 회차가 끝난 뒤 `docker compose down` 없이
통계 분석 회차를 이어서 진행해도 됩니다.

## 통계 분석 회차 상세

전처리한 카페 매출 데이터에 **상관분석과 회귀분석**을 적용해
매출에 가장 큰 영향을 주는 변수를 찾고, 결과지를 채우는 실습입니다.

로드·정제 → 탐색(히스토그램·박스플롯) → 상관계수 히트맵 → 다중 회귀(OLS) → 인사이트 정리

노트북 마지막의 **결과지 빈칸**(가장 강한 상관 변수 / R² / 유의한 변수 / 비즈니스 제안)을
직접 채우는 것이 이 회차의 과제입니다. 필요한 라이브러리(pandas, seaborn, statsmodels)는
이미지에 포함되어 있어 추가 설치가 필요 없습니다.

## 실습 데이터 (data/cafe_sales.csv)

3개 매장 × 120일, 총 363행. 요일·날씨·기온에 따라 매출이 변하도록 생성했고,
전처리 대상 문제를 **일부러 심어** 두었습니다:

| 문제 | 내용 | 처리 단계 |
|---|---|---|
| 결측치 | weather 18건, sales 12건 | Step 2 (전략이 서로 다름!) |
| 이상치 | 매출 9,900만/8,500만/음수, 기온 250도 | Step 3 (IQR + 도메인) |
| 중복 | 3건 (store_id+date 기준) | Step 4 |
| 범주형 | weather/weekday 문자열 | Step 5 (인코딩) |

마지막 보너스 셀에서 정제된 데이터로 선형회귀를 돌려 R²를 확인합니다 —
"전처리가 예측을 위한 것"임을 체감시키고 다음 회차(모델링)로 자연스럽게 연결됩니다.

## 자주 겪는 문제

- **data/cafe_sales.csv가 없다고 나옴** → 노트북 기준 경로는 `work/` 안입니다. 코드의 `data/cafe_sales.csv` 그대로 두고, 노트북을 `work/` 위치에서 열었는지 확인
- **describe에서 이상치가 안 보임** → inferSchema=True를 빼고 로드한 경우 전부 문자열이라 통계가 이상해집니다
- **초기화** → `docker compose down` 후 `up -d` (CSV는 저장소 파일이라 항상 원본 유지)
